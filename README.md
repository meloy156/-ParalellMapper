## ✨ Основные возможности

Данный проект решает задачу параллельной обработки данных, не прибегая к помощи стандартного `java.util.concurrent`. Вся работа с потоками и примитивами синхронизации реализована вручную:

- **⚡ Отсутствие активного ожидания (No Busy Waiting):** Потоки не крутятся в бесконечных циклах `while(true)`, сжигая CPU. Используются мониторы объектов (`synchronized`) и методы `wait()`/`notifyAll()`. Потоки спят ровно до того момента, пока в очереди не появится работа.
- **🛡️ Изоляция клиентов (Client Isolation):** Один `ParallelMapper` может безопасно использоваться десятками клиентов одновременно. Задачи перемешиваются в общей очереди, но благодаря локальным счетчикам (Counter/Latch) каждый клиент ожидает завершения *только своих* вычислений.
- **🚑 Отказоустойчивость (Exception Safety):** Если переданная функция выбрасывает исключение (`NullPointerException`, `IOException` и т.д.), рабочий поток **не умирает**. Ошибка перехватывается, сохраняется в изолированный массив и пробрасывается строго вызывающему клиенту. Пул продолжает выполнять другие задачи.
- **📦 Строгая FIFO-очередь:** Собственная потокобезопасная очередь гарантирует выполнение задач в порядке их поступления (First-In-First-Out).
- **🔢 Поддержка шага (`step`):** Высокоуровневые методы `IterativeParallelism` умеют работать с подмножествами элементов (например, обходить элементы с шагом 2 или 5), сохраняя при этом параллелизм.
- **🔄 Грациозное завершение:** Метод `close()` позволяет корректно дождаться завершения уже поставленных задач и только потом останавливает рабочие потоки, освобождая ресурсы.

## 🏗 Архитектура (под капотом)

Проект построен на классическом паттерне **"Производитель-Потребитель" (Producer-Consumer)**.

1. **Поток-клиент (Producer):** Вызывает метод `map()`, передавая функцию и список элементов. Разбивает работу на атомарные задачи (`Runnable`) и помещает их в общую очередь.
2. **Очередь (Shared Queue):** Является точкой синхронизации. Если очередь пуста — потребители спят (`wait`). Если клиент добавил задачу — он будит потребителей (`notifyAll`).
3. **Рабочие потоки (Consumer):** Фиксированное количество потоков, созданных в конструкторе `ParallelMapperImpl`. Они бесконечно забирают задачи из очереди и выполняют их.

**Ключевая особенность сохранения порядка:** Потоки выполняют задачи в случайном порядке (кто первый освободился). Однако результаты записываются в массив клиента строго по индексу `idx`, который "зашит" внутри каждой задачи (лямбды). Поэтому итоговый список всегда возвращается в правильном порядке, независимо от того, какой поток и когда выполнил конкретную задачу.

## 🧩 Компоненты системы

| Компонент | Роль в системе | Ключевые особенности |
| :--- | :--- | :--- |
| `SimpleQueue<T>` | Очередь задач | Использует `ArrayDeque` + `synchronized`/`wait`/`notifyAll`. Защищает от гонок данных. Блокирует потоки при пустой очереди. |
| `ParallelMapperImpl` | Пул потоков (Thread Pool) | Управляет жизненным циклом потоков. Реализует интерфейс `ParallelMapper` и `AutoCloseable`. Обеспечивает потокобезопасный метод `map()`. |
| `IterativeParallelism` | Высокоуровневый API | Нарезает исходный список на `chunks`, отправляет в маппер и склеивает (reduce) результаты. Не создает собственных потоков, если передан маппер. |
| `Counter` (внутр. класс) | Примитив синхронизации | Локальный счетчик для каждого вызова `map()`. Позволяет клиенту заснуть и проснуться ровно тогда, когда все его задачи выполнены. |

## 💻 Примеры использования

### 1. Высокоуровневый API (`IterativeParallelism`)
Идеально подходит для параллельной фильтрации, маппинга и поиска по коллекциям. Вам не нужно думать о потоках — просто опишите логику.

import iterative.ParallelMapperImpl;
import iterative.IterativeParallelism;
import java.util.List;

public class Example {
    public static void main(String[] args) throws InterruptedException {
        // Создаем пул из 4 рабочих потоков
        try (ParallelMapperImpl mapper = new ParallelMapperImpl(4)) {
            IterativeParallelism parallel = new IterativeParallelism(mapper);
            
            List<Integer> numbers = List.of(10, 20, 30, 40, 50);
            
            // 1. Находим индексы чисел, которые делятся на 20 (результат: [1, 3])
            int[] indices = parallel.indices(4, numbers, x -> x % 20 == 0);
            
            // 2. Параллельно умножаем каждый элемент на 10
            List<Integer> multiplied = parallel.map(4, numbers, x -> x * 10);
            
            System.out.println(multiplied); // [100, 200, 300, 400, 500]
        }
    }
}


2. Низкоуровневый API (ParallelMapperImpl)
Если вам нужен полный контроль над задачами (например, для асинхронной загрузки данных из сети).

```java
import iterative.ParallelMapperImpl;
import java.util.List;

public class LowLevelExample {
    public static void main(String[] args) throws InterruptedException {
        ParallelMapperImpl pool = new ParallelMapperImpl(8);
        
        List<String> urls = List.of(
            "https://example.com/data1", 
            "https://example.com/data2"
        );
        
        // Асинхронно скачиваем данные в 8 потоков
        List<String> contents = pool.map(url -> {
            // Имитация долгой сетевой операции
            Thread.sleep(100); 
            return "Content of " + url;
        }, urls);
        
        pool.close(); // Корректно останавливаем потоки
    }
}


```
🛠 Установка и сборка
Требования:

JDK 17 или выше (проект использует современные фичи, такие как try-with-resources и лямбды).

Сторонние JAR-библиотеки тестов (лежат в папке lib/).

Шаг 1. Клонирование репозитория:

```bash
git clone https://github.com/your-username/parallel-mapper.git
cd parallel-mapper
```

Шаг 2. Создание директории для классов:
Создайте папку out, куда будут компилироваться .class файлы:
``bash
bash
mkdir out
``

Шаг 3. Компиляция (Windows):

```cmd
javac -cp "lib/*" -d out src/iterative/*.java
```
Шаг 3. Компиляция (Linux / macOS):

```bash
javac -cp "lib/*" -d out src/iterative/*.java
Примечание: Обратите внимание на разделитель Classpath. В Windows это ;, в Unix-системах — :. Флаг -d out указывает компилятору, куда складывать скомпилированные файлы.
```

Шаг 4. Запуск (пример):
Если у вас есть свой Main класс, запустить его можно так:

```cmd
java -cp "out;lib/*" your.package.Main
```
