## ✨ Ключевые особенности

- **Отсутствие активного ожидания (No Busy Waiting):** Потоки не крутятся в цикле `while(true)`, пожирая процессор. Вместо этого они засыпают через `wait()` и просыпаются ровно в тот момент, когда появляется работа (`notifyAll()`).
- **Изоляция клиентов:** Один `ParallelMapper` может обслуживать одновременно десятки клиентов. Задачи перемешиваются в общей очереди, но благодаря локальным счетчикам (Counter/Latch) каждый клиент ждет завершения *только своих* задач.
- **Отказоустойчивость (Exception Safety):** Если функция, переданная клиентом, выбрасывает исключение (`NullPointerException`, `IOException` и т.д.), это не убивает рабочий поток. Ошибка сохраняется, а затем пробрасывается конкретному клиенту. Пул продолжает работу.
- **Потокобезопасная очередь (FIFO):** Задачи строго выполняются в порядке поступления (First-In-First-Out), что гарантирует предсказуемость.
- **Грациозное завершение:** Метод `close()` позволяет корректно дождаться завершения уже начатых задач и только потом останавливает потоки, освобождая ресурсы.

## 🏗 Архитектура проекта

Система построена на классическом паттерне **"Производитель-Потребитель" (Producer-Consumer)**.

1. **Клиент (Поток-клиент):** Вызывает метод `map()`, передает функцию и список элементов. Разбивает работу на `Runnable`-задачи и кладет их в очередь.
2. **Очередь (SimpleQueue):** Является точкой синхронизации. Блокирует клиентов (если очередь переполнена) и рабочих (если очередь пуста).
3. **Рабочие потоки (Worker Threads):** Фиксированное количество потоков, созданных в конструкторе `ParallelMapperImpl`. Они бесконечно достают задачи из очереди и выполняют их, записывая результаты в массивы клиентов по строгим индексам.

## 🧩 Компоненты системы

### 1. `SimpleQueue<T>`
Кастомная потокобезопасная очередь.
- **Как работает:** Использует монитор объекта (`synchronized`), методы `wait()` и `notifyAll()`.
- **Зачем нужна:** Гарантирует, что при отсутствии задач потоки спят, а при их появлении — просыпаются. Использует `ArrayDeque` как внутреннее хранилище.

### 2. `ParallelMapperImpl`
Собственно сам пул потоков.
- Реализует интерфейс `ParallelMapper`.
- Принимает в конструкторе количество потоков `threads`.
- Метод `map(Function, List)` возвращает `List<R>` — список результатов в том же порядке, что и исходный, но вычисленных параллельно.

### 3. `IterativeParallelism`
Высокоуровневая обертка над маппером, реализующая интерфейсы `ScalarIP` и `ListIP`.
- Не создает собственных потоков, если ей передан `ParallelMapper`.
- **Как работает:** Нарезает исходный список на куски (`chunks`), отправляет каждый кусок в `mapper.map()`, а затем "склеивает" промежуточные результаты (например, выбирает максимум из локальных максимумов).
- Поддерживает шаг (`step`) и работу с предикатами/компараторами.

## 💻 Примеры использования

### Пример 1: Использование `IterativeParallelism` (Высокоуровневый API)
```java
import iterative.ParallelMapperImpl;
import iterative.IterativeParallelism;
import java.util.List;

public class Example {
    public static void main(String[] args) throws InterruptedException {
        // Создаем пул из 4 потоков
        try (ParallelMapperImpl mapper = new ParallelMapperImpl(4)) {
            IterativeParallelism parallel = new IterativeParallelism(mapper);
            
            List<Integer> numbers = List.of(10, 20, 30, 40, 50);
            
            // Находим индексы четных чисел
            int[] evenIndices = parallel.indices(4, numbers, x -> x % 20 == 0);
            // Результат: [1, 3] (числа 20 и 40)
            
            // Умножаем все элементы на 2
            List<Integer> doubled = parallel.map(4, numbers, x -> x * 2);
        }
    }
